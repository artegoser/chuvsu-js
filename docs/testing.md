# Проверка расписания v5

Ни один автотест не равен ручной проверке всех значений. Ожидаемые JSON были
получены автоматически, поэтому сами по себе они не считаются доказательством
правильности.

Проверка разделена на независимые слои:

1. Каждый JSON повторно строится основным парсером и сравнивается целиком.
2. Отдельный DOM-аудитор читает исходный HTML напрямую и проверяет предмет, тип,
   номер, время, недели, чередование, связи, замены и переносы. Он не использует
   функции парсинга расписания.
3. Точечные небольшие HTML-примеры проверяют группы, преподавателей и аудитории,
   семестр, обе сессии, экзамены, консультации, подгруппы, ДОТ, замены,
   преподавателя «вместо», переносы и отсутствие данных.
4. Доменные тесты отдельно проверяют устойчивость ID, неоднозначность,
   объединение проекций, применение замен и календарное раскрытие серий.
5. Корпус обязан содержать заявленные классы данных. Если из него исчезнут
   переносы, замены, датированные занятия или ДОТ, тест покрытия корпуса упадет.
6. `pnpm test:coverage` устанавливает минимальный порог для ядра расписания:
   95% строк, 94% функций и 80% ветвей.
7. Live-тест сравнивает результат с текущими страницами портала, но не заменяет
   замороженные фикстуры.

Ручная проверка всех полей 42 файлов не проводилась. Ручная выборочная проверка
используется для сложных случаев, а воспроизводимую гарантию дают перечисленные
независимые проверки и порог покрытия.
